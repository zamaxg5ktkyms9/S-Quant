# Slack 報告

## 2つの経路の使い分け

| 経路 | いつ使う |
|---|---|
| A: Stop hook 自動送信 | セッション終了時。**最後のアシスタントメッセージが自動で Slack に送られる**ため、セッションの最終応答を報告様式で書けば追加作業不要 |
| B: webhook へ明示送信 | 着手前の完了条件送信 / 長時間処理の途中経過 / セッションが続くのに今すぐ報告したいとき |

## 経路 B: 明示送信（動作検証済みコマンド）

```bash
cd <リポジトリルート> && WEBHOOK=$(grep '^SLACK_WEBHOOK_URL=' .env | cut -d= -f2- | tr -d '"' | tr -d "'") \
  && curl -s -X POST -H 'Content-Type: application/json' -d @- "$WEBHOOK" <<'EOF'
{"text": "ここに報告本文（\n で改行、*太字* が使える）"}
EOF
```

- 成功時のレスポンスは `ok` の1語。それ以外が返ったら送信失敗として扱い、再試行する。
- 1メッセージは 2800字以内を目安に（超える場合は分割）。

## 報告に必ず含める項目（CLAUDE.md 準拠）

### 着手前（完了条件の解釈）
1. タスクの完了条件を自分の言葉で列挙。
2. これから行う手順の概要。
3. 所要時間見込み（**必ず最良〜最悪の幅＋根拠の式**。単一数字の断言禁止）。

### 完了時
1. **実施した操作のサマリー**（何をどう変えたか。コミットハッシュがあれば添える）。
2. **成功・失敗・スキップした項目と、その理由**（失敗を「概ね成功」と言い換えない。
   テスト FAIL やエラーはそのまま書く）。
3. **オーナーが翌日確認すべき点**（なければ「なし」と明記）。

### 長時間処理の途中経過
- 実測 ETA が初期見積りの2倍を超えたら、その時点で一度報告する。

## 禁止事項

- Webhook URL を Slack 本文・ログ・コミット・標準出力に出すこと（`echo $WEBHOOK` 禁止）。
- 失敗・スキップの隠蔽や楽観的な言い換え。
- 所要時間・成績数値の断言（幅＋根拠で書く）。
- 報告なしでのセッション終了（経路 A があるため、最終応答を報告様式で書けば満たせる）。
