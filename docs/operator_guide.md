# Operator Guide — S-Quant Phase 1

> **対象**: S-Quant の半自動運用を担当するオペレーター（=あなた）
> **想定環境**: SBI証券（単元株・100株単位）+ Slack + GitHub Actions
> **戦略**: 押し目モメンタム（[docs/backtest_report.md](backtest_report.md) 参照）

---

## 0. 全体フロー（1日のリズム）

```
20:15 JST  GitHub Actions が自動シグナル生成 → Slack通知
            └─→ "SIGNAL" 通知が来たら、当日夜のうちに翌朝の発注準備

翌 09:00   始値確認 → 発注可否を判断
   ├─ 始値 > 前日終値 × 1.02       → ❌ エントリー見送り
   ├─ 始値 ≤ 推奨ストップ価格      → ❌ エントリー見送り
   └─ それ以外                      → ✅ ③ へ

   09:00以降の任意時刻  ③ SBI証券で「成行買い」発注 → 即時約定
   約定直後             ④ OCO注文セット（利確指値 + 損切り逆指値）
   約定確認後           ⑤ Slack に約定価格・株数を返信

保有中
  毎営業日 20:15  システムがトレーリングストップ価格を再計算
                  └─→ "TRAILING UPDATE" 通知が来たら、SBIで逆指値を切り上げ

  5営業日経過時    システムが "TIME_STOP" 通知 → 翌朝 OCO キャンセル + 成行売却
  ザラ場で異常急落  オペレーター判断で任意の手動成行売却（緊急離脱）
```

## 1. Slack 通知の見方

### 1.1 SIGNAL 通知（エントリーシグナル発生）

```
🟢 [S-Quant] SIGNAL 2354.T (yyyy-mm-dd 引け後)
  銘柄: 2354.T (Y's Holdings)
  推奨株数: 100株
  想定エントリー価格: ¥672  (前日終値)
  推奨ストップ価格: ¥655   (-2.5%)
  推奨利確価格:   ¥712   (+6.0%)
  ギャップアップ上限: ¥685  (前日終値 × 1.02)
  RSI(14): 46.2
```

→ 翌朝 9:00 にこの銘柄の発注可否を判断する。

### 1.2 TRAILING UPDATE 通知（保有中の逆指値更新）

```
🔵 [S-Quant] TRAILING UPDATE 2354.T
  現ストップ価格: ¥672 → 新ストップ価格: ¥686
  根拠: 直近高値 ¥710 - 1.5 × ATR(14) ¥16 = ¥686
  → SBI証券で OCO の逆指値を ¥686 に変更してください
```

→ SBIアプリで該当ポジションのOCO逆指値を ¥686 に修正する。

### 1.3 TIME_STOP 通知（5営業日経過）

```
🟡 [S-Quant] TIME_STOP 2354.T
  保有5営業日経過 → 翌朝 OCO をキャンセルして成行売却してください
  現在の評価額: ¥69,800 (P&L: +¥1,800)
```

→ 翌朝 SBI で OCO 注文をキャンセル → 即座に成行売り発注。

### 1.4 CIRCUIT BREAKER 通知（累積損失上限到達）

```
🔴 [S-Quant] CIRCUIT BREAKER TRIPPED
  累積実現損失: ¥-30,100 ≥ ¥30,000
  全取引を停止しました。手動リセットが必要です。
```

→ サーキットブレーカー発動。これ以上の新規エントリーは停止される。手動リセットまで本システムは IDLE 状態となる。原因分析後、Sheets の `circuit_breaker` タブを編集してリセット。

## 2. SBI証券UI での発注手順

> **前提**: SBI証券にログイン済み、対象銘柄を「銘柄検索」または「お気に入り」から開ける状態。
> **UI**: PC版 SBI証券 (https://www.sbisec.co.jp/) を想定。スマホ版でも操作項目は同じ。

### 2.1 STEP 1: 始値確認（9:00 直後）

1. 「国内株式」→「銘柄検索」で対象銘柄コード（例: 2354）を入力
2. 銘柄ページの「現在値」欄を確認
3. 「始値」欄が **前日終値 × 1.02 以下** であることを確認
   - 例: 前日終値¥672 → 始値¥685 以下なら OK、¥686 以上ならスキップ
4. 「始値」欄が **推奨ストップ価格を上回っている** ことを確認
   - 例: 推奨ストップ¥655 → 始値¥655 以下なら絶対スキップ（即ロス確定）

### 2.2 STEP 2: 成行買い発注

1. 銘柄ページ右上「現物買」ボタンをクリック
2. 注文画面で以下を入力:
   - **市場**: 東証
   - **株数**: Slack通知の「推奨株数」（例: 100株）
   - **価格**: 「**成行**」を選択
   - **期間**: 当日中
   - **預り区分**: 特定預り（通常）
   - **取引パスワード**: 入力
3. 「注文確認」→「注文発注」
4. 約定通知が来たら、約定価格を控える（OCOセットで使う）

### 2.3 STEP 3: OCO 注文セット（約定直後）

> **OCO (One-Cancels-the-Other)**: 利確指値と損切り逆指値を同時に出し、片方が約定したら他方を自動キャンセルする注文方式。

1. SBI証券「国内株式」→「保有証券」で約定した銘柄を確認
2. 該当銘柄の「売却」ボタン →「特殊注文」→「OCO」を選択
3. 注文画面で以下を入力:
   - **株数**: 約定株数全部（例: 100株）
   - **指値（利確）**: 約定価格 × 1.06
     - 例: 約定¥672 → 指値 ¥712（小数点以下は呼値刻みに合わせる、¥1,000未満は1円刻み）
   - **逆指値（損切り）**: 約定価格 × 0.975
     - 例: 約定¥672 → 逆指値 ¥655（同上呼値刻み）
     - 「トリガー価格」¥655、「逆指値後の注文」**成行** を選択
   - **期間**: 「今週中」または「期間指定」最長まで（最大10営業日程度）
4. 「注文確認」→「注文発注」
5. 注文一覧で OCO 2件が出ていることを確認

> **重要**: OCO は SBI 標準機能だが、両側の有効期限は別管理。期限が切れたら **再セット必須**。Slack通知 "TRAILING UPDATE" が来た時に併せて期限も確認する習慣をつけると良い。

### 2.4 STEP 4: Slack に約定報告

Slack の SIGNAL 通知スレッドに以下のフォーマットで返信:

```
約定: 2354.T  ¥674 × 100株  09:03
OCO: 利確 ¥715 / 逆指値 ¥657 セット済
```

→ システム（手動運用の場合は次回 GitHub Actions 実行時）が Sheets に保存する。

### 2.5 STEP 5: トレーリングストップ更新（毎営業日 20:15 以降）

1. Slack "TRAILING UPDATE" 通知を確認
2. SBI証券「注文照会」→ 対象銘柄の OCO 注文を選択
3. 「**訂正**」→ 逆指値の「トリガー価格」を新しい値に変更
4. 指値（利確）は変更不要
5. 「注文確認」→「訂正発注」

### 2.6 STEP 6: タイムストップ売却

1. Slack "TIME_STOP" 通知を確認
2. 翌朝 09:00 以降に SBI証券「注文照会」→ OCO 注文を**両方キャンセル**
3. 「現物売」→ **成行** → 全株数で売却発注
4. 約定後、Slack に売却報告

## 3. 緊急対応

### 3.1 ザラ場で持株が異常急落（システム通知前）

- **前日終値比 -5% 超下落** など、明らかに想定外の急落が発生した場合
- 引け後シグナル更新を待たず、**オペレーター判断で即座に手動成行売却**
- 例: 悪材料ニュース、市場全体の急落、東証障害等

手順:
1. SBI証券「注文照会」→ OCO 注文を**両方キャンセル**
2. 「現物売」→ **成行** → 全株数で売却
3. Slack に経緯を記録

### 3.2 SBI証券側の障害・発注不能

- SBI 側のシステム障害で OCO セットができない場合
- 暫定対応: 逆指値（単体）だけでも入れておく
- 障害復旧後に OCO に切り替え

### 3.3 GitHub Actions が動かない

- 20:15 JST に Slack 通知が来ない場合
- GitHub リポジトリ → Actions タブ → 実行ログを確認
- よくある原因: J-Quants 認証エラー（APIキー更新が必要）、レートリミット
- 復旧後、当日のシグナル通知は手動で `python scripts/daily_runner.py` を叩いて再生成可

### 3.4 サーキットブレーカー発動

- 累積実現損失が ¥30,000 を超えると自動停止
- 原因分析:
  - 連敗が続いた → 戦略の見直し（market regime change か、ロジック劣化か）
  - 想定外の大損1件 → エントリー条件の追加検討
- リセット手順: Sheets の `circuit_breaker` タブで `is_tripped=FALSE` に手動編集

## 4. Phase 1 Paper Trading 開始チェックリスト

実運用開始前に以下をすべて ✅ にすること。

### 4.1 環境セットアップ

- [ ] GitHub Secrets に以下が設定済み
  - [ ] `GCP_SA_KEY_JSON` (Google Sheets サービスアカウントJSON)
  - [ ] `SPREADSHEET_ID` (運用用 Google Sheet ID)
  - [ ] `SLACK_WEBHOOK_URL`
  - [ ] `JQUANTS_API_KEY` (or refresh token)
- [ ] Google Sheets に6タブ（portfolio, trades, circuit_breaker, run_log, pending_signals, recent_sales, snapshots）が存在
- [ ] サービスアカウントが Sheet の編集権限を持つ
- [ ] Slack Webhook が有効（テスト通知で確認）

### 4.2 コード・データ

- [ ] `data/universe.csv` が最新（株価帯 ¥100〜¥1,000、282銘柄程度）
- [ ] `data/earnings_calendar.csv` が向こう3ヶ月分カバー
- [ ] `pytest tests/unit` が全PASS（170件）
- [ ] `python scripts/dry_run.py --date {当日}` がエラーなく完走
- [ ] 直近のバックテスト（[docs/backtest_report.md](backtest_report.md)）の数値を理解している

### 4.3 GitHub Actions

- [ ] `.github/workflows/daily.yml` の cron が `20:15 JST` (= `15 11 * * 1-5` UTC) になっている
- [ ] 直近の Actions 実行が成功している（dry_run=true で1回テスト）
- [ ] エラー時 Slack 通知が来る設定になっている

### 4.4 SBI証券側

- [ ] SBI証券アカウントログイン情報を控えている
- [ ] 国内株式現物の取引ができる状態（信用取引・先物等は不要）
- [ ] 「ゼロ革命」適用条件を満たしている（各種報告書を電子交付）
- [ ] OCO 注文機能が使えることを確認（必要なら一度テスト発注 → 即キャンセル）
- [ ] 入金残高が ¥100,000 以上

### 4.5 オペレーター運用準備

- [ ] 本ガイド ([docs/operator_guide.md](operator_guide.md)) を一度通読
- [ ] 平日朝 9:00 にSlack通知をチェックできる環境（PC or スマホ）
- [ ] 緊急時に SBI 取引できる環境
- [ ] 想定外の事象が起きた場合の対応方針（売却 or ホールド）を自分の中で決めている

### 4.6 初週の運用

- [ ] 初回エントリー発生時、本ガイドを開きながらゆっくり操作する
- [ ] 1週間目は毎日 SBI 約定情報 vs Slack 通知 vs Google Sheets を**目視照合**
- [ ] 異常なし → 通常運用へ

## 5. 月次レビュー（運用2ヶ月目以降）

毎月末に以下を確認。

| チェック項目 | 目安 | 異常時のアクション |
|---|---|---|
| 月次シグナル数 | バックテスト実測 月2件 | ±50% を超えるなら戦略を点検 |
| 月次リターン | バックテスト実測 +0.40% | -2% を超えるマイナスなら戦略を点検 |
| 勝率 | バックテスト実測 44.9% | 30% を下回るなら一時停止検討 |
| 最大DD | バックテスト実測 -16.8% | -20% に近づいたらサイズダウン検討 |
| Slack通知の信頼性 | 100% | 欠落があれば GHA / J-Quants を調査 |

実測がバックテストを大幅に下回り続ける場合は、戦略本体の見直し（[docs/backtest_report.md](backtest_report.md) Section 11.3 Mid-term Improvement Candidates 参照）に進む。
