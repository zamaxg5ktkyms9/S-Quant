## 戦略コンセプト

本システムは「**5×25日 MA クロスで上昇トレンド開始を検知し、上向き中期 MA と出来高サージで実需を確認したうえで 2銘柄分散保有する**」設計です（トレンドフォロー型）。

「下がっている中で買う」（押し目モメンタム）ではなく「**上がり始めた確認後に買う**」アプローチ。短期 MA が中期 MA を上抜けて、かつ中期 MA 自身が上向きの局面に絞ることで、ダマシブレイクと「落ちてくるナイフ」掴みの両方を回避する。

各銘柄独立で最大5営業日のタイムストップ・OCO（利確+6%、損切り-2.5%、ATR×2 程度のトレーリング）で機械的に手仕舞い、含み損の長期化を防ぐ。

**分散方針（段階拡大）**:
- **Phase 1（¥200,000）**: 最大 **2 銘柄**同時保有（1銘柄あたり予算 ≒ ¥100,000、対象株価 ¥100〜¥1,000）
- **Phase 2（¥300,000）**: 最大 **3 銘柄**同時保有
- **Phase 3（¥1,000,000）**: 最大 **3 銘柄**同時保有

単元株（100株単位）取引を使用し、SBI証券の逆指値・OCO注文でザラ場の損切り・利確を**各銘柄独立で**機械化する。

> **押し目モメンタム（A1/B 戦略）からの転換根拠**
> - A1 単一銘柄: OOS 2023 PF 0.43、OOS 2025 PF 0.77 → 2/2 窓 FAIL
> - B 2銘柄分散押し目: OOS 2023 PF 0.61 → ❌ FAIL（分散効果はあったが基準未達）
> - C 2銘柄分散 MA クロス: OOS 2023 PF 0.85、OOS 2024 PF 1.21 ✅、OOS 2025 PF 1.36 ✅ → 2/3 窓 PASS
> - 「下がってる中で買う」自体が日本小型株では構造的に不利、「上がり始め確認」への転換で改善

## スクリーニング条件

流動性の低い銘柄・財務的に脆弱な銘柄・割高銘柄を事前に除外し、シグナルの誤検知を減らす。

| 項目 | 条件（Phase 1） | 根拠 |
|---|---|---|
| 株価 | **Phase 1: ¥100 〜 ¥500 / Phase 2: ¥100 〜 ¥1,000 / Phase 3: ¥100 〜 ¥3,000** | 1銘柄あたり予算 ≈ 投資資本 / 同時保有上限 を超えないよう Phase 別に上限。下限¥100はスプレッド過大回避 |
| 時価総額 | ¥30億以上 | 極小型株はニュース1本で急騰急落しやすく、テクニカル分析が機能しにくい |
| 流動性 | 5日平均売買代金 ¥1億以上 | 売買代金が薄い銘柄は逆指値発動時のスリッページが大きくなる |
| PBR | 0.5 〜 2.0 倍 | 0.5倍未満は解散価値割れ（業績悪化懸念）、2.0倍超は割高 |
| 自己資本比率 | 30%以上 | 30%未満は財務レバレッジが高く、外部環境の変化に脆弱 |
| 決算ブラックアウト | ±3営業日は除外 | 決算前後のギャップリスクを回避 |

> **用語**
> - *PBR（株価純資産倍率）*: 株価 ÷ 1株当たり純資産。企業の解散価値に対する割安・割高の目安。
> - *自己資本比率*: 純資産 ÷ 総資産。高いほど借金が少なく財務的に安定。

## シグナル条件（C 戦略 = MA クロス + トレンドフィルタ）

3条件すべてを満たした銘柄のみをエントリー候補とする。

| 条件 | 内容 | 根拠 |
|---|---|---|
| ① クロス | **5日MA > 25日MA** | 短期が中期を上抜け = 上昇基調確認（疑似ゴールデンクロス継続条件） |
| ② 中期トレンド | **25日MA(today) > 25日MA(today - 20)** | 中期トレンド自身が上向きであることをフィルタ、ダマシ排除 |
| ③ 出来高サージ | 当日出来高 > 20日平均出来高 × 1.2 | 実需を伴う動きを確認、ダマシブレイク抑制 |

> **押し目モメンタム（A1/B）からの撤廃条件**
> - RSI 押し目ゾーン (35-60): 撤廃 — 「下がっている中で買う」概念を捨てる
> - 75日MA 上のトレンド条件: 撤廃 — 25日MA 上向きで代替
> - ボラ収縮（20日 std < 過去平均）: 撤廃 — 上昇トレンド中はボラが拡大することがあるため

> **C 採用までの履歴**
> 1. **旧S株版「RSI(5)<45 + 終値>5日MA」**: RSI(5)が短期反転で急上昇するため数学的に成立せず。実ライブ（2026-05-22）スクリーナー通過29件中シグナル0件。
> 2. **A1: 押し目モメンタム RSI(14) 35-60 + 75日MA上 + ボラ収縮 + 出来高サージ**: Grid Search 月+0.40%/PF 1.20 だが Walk-Forward で過剰最適化検出、撤退。
> 3. **B: 同じシグナル + 2銘柄分散 ¥200k**: PF 0.43→0.61 と改善も robust 未達、撤退。
> 4. **C: 5×25日 MA クロス + 25日MA 上向き + 出来高サージ + 2銘柄分散 ¥200k**: 三窓 2/3 ✅ Robust 確定、採用。

> **用語**
> - *MA（移動平均）*: 過去N日間の終値の平均。トレンド方向の平滑化。5日MA と 25日MA の差分が短期勢いを示す。
> - *MA 上向き*: 当日 MA 値が N 日前 MA 値より大きい状態。トレンドの傾きが上方であることを意味する。
> - *出来高サージ*: 直近出来高が平均より高い状態。需給逼迫・実需介入の指標。

候補が複数の場合は **RSI昇順 → 出来高サージ率降順 → PBR昇順** でランキングし、**空きスロット数まで（Phase 1: 最大2件、Phase 2/3: 最大3件）を翌営業日のエントリー候補としてキューに入れる**。
※ RSI はランキング順位付けには使うが、C 戦略のフィルタには使わない（押し目モメンタムからの差分）。

**保有銘柄の重複排除**: スクリーナー段階で既保有 ticker（`held_tickers` セット）はフィルタアウトする。同一銘柄を2スロットに入れることはしない（損益管理と分散効果の崩壊を防ぐ）。

## 発注数量（動的資金分配）

```
1銘柄予算 = floor(残キャッシュ / 残空きスロット数)
最悪ケース執行価格 = 前日終値 × (1 + 2%)  ← ギャップアップ上限
最大株数 = floor(1銘柄予算 / 最悪ケース執行価格)
発注株数 = floor(最大株数 / 100) × 100      ← 単元株なので100株単位
```

- **残キャッシュ** = 投資資本 - 既保有 Position の合計 cost_basis
- **残空きスロット数** = MAX_POSITIONS - 既保有 Position 数（Phase 1: 2 - n）

Phase 1（¥100,000、同時保有 2銘柄）でスロット 0 件埋まっている状態で株価¥400の銘柄をエントリーする例:
- 1銘柄予算 = floor(100,000 / 2) = ¥50,000
- 最悪ケース執行価格 = 400 × 1.02 = 408
- 最大株数 = floor(50,000 / 408) = 122
- 発注株数 = floor(122 / 100) × 100 = **100株**
- 実投下額 ≈ ¥40,000、残キャッシュ ≈ ¥60,000（次の1銘柄予算は ¥60,000 / 1 = ¥60,000 → 単元株調整で ≈ ¥50,000 程度に）

## 発注フロー

### エントリー（1〜N銘柄、N = 空きスロット数）

| ステップ | 時刻 | 担当 | 内容 |
|---|---|---|---|
| 1 | 当日 20:15 | システム | 空きスロット数までシグナルをランキング上位順に検出 → Slack通知（銘柄ごとに 推奨株数・想定エントリー価格・**推奨ストップ価格**・**推奨利確価格** を一括表示） |
| 2 | 翌営業日 9:00 | オペレーター | **各銘柄独立に**始値確認。下記いずれかでその銘柄のエントリー見送り:<br>・始値 > 前日終値 × 1.02（ギャップアップ）<br>・始値 ≤ 推奨ストップ価格（ギャップダウンで即ストップ圏内）<br>他の銘柄は通常通り進行 |
| 3 | 9:00以降の任意時刻 | オペレーター | SBI証券で**銘柄ごとに成行買い**発注 → 即時約定 |
| 4 | 約定直後 | オペレーター | **銘柄ごとに**SBI証券で OCO 注文をセット:<br>・利確指値: エントリー価格 × 1.06（+6%）<br>・損切り逆指値: エントリー価格 × 0.975（-2.5%） |
| 5 | 約定情報 | オペレーター | Slack の専用スレッドに**全銘柄の**約定価格・株数を返信 → システムが Sheets に複数行で保存 |

### 保有中の出口管理（各銘柄独立）

| 出口 | 発動 | 実装 |
|---|---|---|
| ハードストップ -2.5% | 各銘柄でザラ場価格到達 | OCO逆指値で**自動執行** |
| 利確 +6%（×1.06） | 各銘柄でザラ場価格到達 | OCO指値で**自動執行** |
| トレーリングストップ | 毎営業日 20:15 に**各銘柄独立に**システムが計算 | Slack通知 → オペレーターが該当銘柄の SBI 逆指値価格を切り上げ（OCO再セット） |
| タイムストップ（5営業日） | 各銘柄ごとに 5営業日経過 | 5日目の引け後にシステムが通知 → オペレーターが該当銘柄の OCO キャンセル＋翌朝成行売却 |

**出口で空いたスロットの再充填**: 出口当日の引け後シグナル検出フェーズで、その銘柄を含めた残スロット分のエントリー候補をキューに入れる。翌営業日 9:00 始値で新規エントリーが行われる（SBI現物取引のため、売却資金は翌朝の買付余力に反映される）。

## 出口ルール詳細

### 優先順位

| 優先度 | ルール | 発動条件 | 実装 |
|---|---|---|---|
| 1 | ハードストップロス | 株価 ≤ エントリー価格 × (1 - 2.5%) | SBI逆指値（OCO） |
| 2 | トレーリングストップ | 株価 ≤ max(ハードストップ, 直近高値 - 2.5×ATR(14)) | システム計算 → 手動でSBI逆指値更新 |
| 3 | 利確 | 株価 ≥ エントリー価格 × 1.06（+6%） | SBI指値（OCO） |
| 4 | タイムストップ | 保有5営業日経過 | システム通知 → 手動成行売却 |

> **優先順位の根拠（バックテストの保守的扱い）**
> 実運用ではOCOに利確指値と逆指値が同時にセットされるため、ザラ場で先に到達した方が約定する。しかしバックテストでは1日の中の到達順序は OHLC からは復元できない。同日に「安値 ≤ ストップ」かつ「高値 ≥ 利確」が両方成立した場合、**保守的にストップ優先**として損失側を計上する。これにより期待値が過大評価されない。
> 実装: `src/squant/domain/position_manager.py` の `evaluate_exit` がこの順序で判定する。

### 利確価格の計算

```
利確価格 = エントリー価格 × (1 + 6%) = エントリー価格 × 1.06
```

**Phase 1（単元株・SBI手数料0円）ではスプレッドコストは実質ゼロ**。S株時代の両端 0.5% 補正（旧式 ≈ ×1.0716）は不要。実装の `compute_take_profit_price` は `spread_rate=0` をデフォルトとし、純粋な ×1.06 を返す。

### パラメータ確定値（Grid Search 2024-2025 ベスト）

| パラメータ | 確定値 | Grid 探索レンジ | 採用根拠 |
|---|---|---|---|
| ハードストップ | -2.5% | （固定） | 最大損失制約を維持 |
| 利確目標 | **+6.0%** | +2% 〜 +6% | Top 4件中3件が +6%。下げると微益決済増えてPF低下 |
| ATR乗数 | **1.5** | 1.5 〜 2.5 | 狭めの方が利益確保が早い。2.5は広すぎて利益逃す |
| トレーリング基準 | 直近高値 - 1.5×ATR | （固定） | 終値ベースはラチェット不成立 |
| ATR期間 | 14 | （固定） | — |
| RSI(14)上限 | **60** | 45 〜 60 | Top 14件すべてが 60。狭めるとシグナル不足 |
| RSI(14)下限 | 35 | （固定） | 押し目ゾーン下限。これ未満は下落圧力強すぎ |
| タイムストップ | 5営業日 | 3 〜 7 | 3/5/7に大差なし、5日が安定 |
| 出来高サージ倍率 | 1.2 | （固定） | — |

> **用語**
> - *ATR（Average True Range）*: 過去N日間の真の値幅平均。銘柄ごとのボラティリティに応じてストップ幅を自動調整。
> - *OCO（One-Cancels-the-Other）*: 利確指値と損切り逆指値を同時に出し、片方が約定したら他方を自動キャンセルする注文方式。
> - *トレーリングストップ*: 上昇につれてストップを切り上げ、利益を守りながらトレンドを追いかける仕組み。下落時は下がらない（ラチェット）。

## リスク管理

### サーキットブレーカー（ポートフォリオ全体）

ポートフォリオ全体の累積実現損失が **投資資本の30%（Phase 1: ¥30,000）** を超えると全取引を停止し、Slack に通知する。手動リセットが必要。
**個別銘柄ではなく合計で判定**するため、1銘柄で大損が出ても他銘柄が稼いでいれば停止しない。

### ステートマシン（複数 Position 対応）

```
IDLE ⇄ ACTIVE（空きスロット > 0 かつ 既保有 ≥ 0）
ACTIVE → SETTLING（最後の Position を出口）→ IDLE
```

各 Position は独立の状態を持ち、Google Sheets の `portfolio` タブに **複数行**で永続化される。
**保有銘柄重複ガード**: スクリーナーは現在の `held_tickers` 集合を引数に取り、シグナル候補から除外する。
**二重エントリー防止**: 同一 ticker が pending_signal にすでに存在する場合、追加検出時はスキップする（べき等性）。

### Phase 1 で特に監視する事項

B-WF（3銘柄分散版での Walk-Forward）後のベースラインとの乖離を計測:

- 月次エントリー回数（2銘柄分散ぶん、単一銘柄期より増加見込み）
- 月次リターン（B-WF ベンチマーク次第、目標は月+0.5%以上 = 年¥100k／Phase 1 ベース）
- 勝率（A1 単一銘柄実測 44.9% / 分散による変化を要観測）
- 約定スリッページ（複数銘柄同時発注時の運用負荷含む）
- 寄りギャップダウンの頻度・規模（銘柄ごとに独立）
- トレーリングストップ更新の手動運用負荷（銘柄数 × 営業日 で線形増加）
- **保有銘柄重複ガードの実効性**（実運用で同一ticker候補が出てこないこと）

実測がバックテストを下回り続ける場合は、戦略本体（シグナル条件 or ユニバース）の見直しを検討。

### Phase移行時のチェックリスト

1. 直前 Phase で「月次期待リターン > 0.5%」の実測が N 月分（Phase 1→2: 2ヶ月、Phase 2→3: 3ヶ月）
2. B-WF 再実行で新 Phase の株価帯・銘柄数でも過半数窓 OOS robust
3. サーキットブレーカー比率を 30% → 15% に厳格化
4. 同時保有銘柄数を 2 → 3 に拡大（`MAX_POSITIONS` 変更）
5. 対象株価帯を拡大（PRICE_MAX 変更）
6. 流動性条件の見直し（Phase 3 では平均売買代金 ¥3億以上に引き上げ検討）
7. SBI証券側の取引履歴・残高と Google Sheets の複数行 portfolio タブの同期確認
