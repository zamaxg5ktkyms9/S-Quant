## 2. 発見事項（深刻度順）

### F-1【実損直結・最重要】サーキットブレーカーは「勝ちで相殺されない総損失和」で判定され、実装どおりなら毎年3〜6ヶ月で発動する

- 根拠: `src/squant/domain/circuit_breaker.py:23-26` — `cumulative_loss_jpy` は負けトレードの損失絶対値のみを加算し、勝ちトレードで減算されない。リセット経路はフェーズ移行時の手動のみ
- 設計との矛盾: `docs/design.md:210`「1銘柄で大損が出ても**他銘柄が稼いでいれば停止しない**」は相殺（純損失）判定を前提とした記述。また §8.14.3 の採用理由②「worstDD -13.1% < CB 15% → **CB 再設計不要**」は、純資産ドローダウン（相殺後）と総損失和（相殺なし）という**比較不能な量の比較**であり、判断根拠として成立していない
- 実測（採用構成の backtest トレード列に実装どおりの CB を適用）: 総損失和が ¥90,000 に到達する日は **2022-04-14 / 2023-06-26 / 2024-04-17 / 2025-05-01**。月+3.07% の最良年 2024 でも4月に発動する。年間総損失和は ¥26万〜37万（閾値の3〜4倍）。一方、相殺後の純損失の最悪値は −¥43,399（2022年）で、¥90,000 に達する年は一つもない
- 失敗シナリオ: 現行の取引頻度（バックテスト水準 ≈ 90件/年）が価格上限 ¥3,000 で回復した場合、**2026年秋〜冬に、戦略が正常に機能していても CB が発動**し全取引が停止する。さらに `daily_runner.py:127-139` は CB 発動中 `_dispatch` を呼ばずに return するため、**保有中ポジションの出口評価・トレーリング更新・タイムストップ通知も止まる**。これは requirements の撤退規定「新規エントリー停止（**保有分は出口ルールで手仕舞い**）」と矛盾する（残るのは証券会社側の逆指値1本のみ）
- 付随バグ: `presentation/slack_formatter.py:169` の CB 通知文言が「累積損失が**¥30,000**に達した」のまま（2世代前の閾値のハードコード）
- 修正方向（提案・未適用）: 判定量を「実現損益の累積（純額）がマイナス方向に ¥90k」または「実現エクイティのピークからの DD ¥90k」に変更し、発動中も HOLDING パイプラインの出口評価だけは走らせる

### F-2【統計的妥当性→実損に波及】ストップ約定価格モデルが楽観的で、期待収益 +1.40%/月 の大半（約 −1.2pt/月）を説明する

- 根拠: `position_manager.py:64-71` / `backtest.py:263` — 当日安値がストップ水準以下なら**常にストップ価格ちょうど**で約定したとみなす。寄付がストップを下抜いて始まった日（ギャップダウン）は、実際の逆指値成行は寄付近辺で約定するため、この仮定は系統的に有利。§4.2 はこれを「スリッページ 0%（**保守的**に…）」と誤って保守側と記載している
- 実測: ギャップ日のみ寄付約定に置き換えた再シミュレーションで年 −0.83〜−1.82pt/月 の劣化（4年平均 +1.40% → +0.21%）。出口の 40〜50% が STOP_LOSS のためストップ約定の仮定が成績を支配する
- 失敗シナリオ: 実運用の期待値が +0.2%/月 前後だとすると、年間期待は ¥100.8k ではなく **¥15k 前後**となり、悪年（2022/2023 相当のレジーム）は月次マイナスが常態化する。運用判定基準の「+0.7% 未満で保留」「0% 未満で撤退」に照らすと、**現行戦略は撤退判定に向かう公算が高い**
- 留意: 寄付約定モデルにも不確実性はある（実際の約定は寄付と当日安値の間に分布）。ただし方向は確実に「ストップ価格ちょうど」より悪く、真値は +0.21% と +1.40% の間の下方寄りと考えるべき。intraday ルックアヘッド（当日高値でトレーリングを引き上げてから当日安値で発動判定、`position_manager.py:53-58`）は約 +0.2pt と小さいことも分解で確認した

### F-3【統計的妥当性】+1.40%/月 は選択に使ったデータ上の値（主張4の帰結）

- 根拠: §1 主張4 の時系列再構成参照。選定に使っていないデータでの固定セット検証はゼロ。WF ベースの不偏推定は +1.03%/月（それも F-2 の楽観約定モデル上の値）
- 失敗シナリオ: 運用判定基準（design/requirements の「良好 > +0.7%」等）が in-sample 値の半値などで設定されているため、**実力が +0.2〜0.5%/月 でも「保留」を長期間さまよい**、資本コスト（機会損失）が累積する
- 修正方向: 判定基準を「選定バイアス込みの楽観値」ではなく WF OOS 平均や本番実測に基づき再設定。以後のパラメータ変更は「グリッド拡張の事前登録（探索空間と停止基準を先に書く）」をルール化する

### F-4【パリティ】バックテストが本番で発生する制約・挙動を模擬していない項目

いずれも単体では中規模だが、すべて backtest に有利または未知方向:

1. **決算ブラックアウト未模擬**: `backtest.py:331-333` は blackouts に空 `set()` を渡す。本番 idle_pipeline は `data/earnings_calendar.csv` 由来の ±3営業日除外を適用（`idle_pipeline.py:150-152`）。バックテストは本番が取れないトレードを含む
2. **T+2 決済ロック未模擬**: backtest は売却当日にキャッシュ復帰し翌日再投資可能（`backtest.py:280`）。本番は SETTLING 状態で `is_settlement_unlocked` が解けるまで新規エントリー不可 → 資本回転が約1営業日ぶん過大
3. **トレーリング更新基準の不一致**: backtest は当日高値でラチェット（`backtest.py:290`、evaluate_exit 内も intraday_high）、本番は当日終値（`holding_pipeline.py:180`）。本番のストップ水準は系統的に低くなる
4. **出口記帳価格の不一致**: 本番は出口判定・記帳とも当日終値（`holding_pipeline.py:154-198`）だが、実際の約定は証券会社の逆指値がザラ場で執行した価格。Sheets 上の実現損益と実際の口座損益が乖離し、CB カウンタも実態とずれる
5. **差金決済除外（recent_sales）未模擬**: 影響は小（同一銘柄の即日再エントリーは稀）

### F-5【保守性・小】その他

- `holding_pipeline.py:126` `isinstance(raw.columns, tuple.__class__)` は常に False の無意味な式（デッドコード）
- `holding_pipeline.py:81-83` 複数ポジション集約で `current.positions.index(pos)` による値等価探索 — 現状は保有銘柄の重複がないため安全だが、同値 Position が並ぶと誤対応する脆い実装
- バックテストの DD はトレード実現損益ベースで、日次時価評価ではない → 保有中の含み損 DD は −13.1% より深くなり得る（§8.15 の Sharpe 等も同様にトレードベース）
- `_state_to_metrics` の月次%は複利でなく初期資本固定割り — 表示上の慣行としては可だが、複利成績とは別物であることに注意

## 4. 総評と最優先の1件

システムのエンジニアリング品質は高い（層分離・テスト・冪等な検証基盤・再現可能な結果 JSON）。docs の数値に捏造や転記ミスはなく、すべて再実行で一致した。**問題は「数値の生成過程」にある**: ①約定モデルが戦略の弱点（ギャップ付きハードストップ多発）にとって最も有利な仮定を置いており、②その楽観値の上で目標達成まで探索空間を広げて選んだ +1.40%/月 が計画の基準値になっている。実力の中心推定は +0.2〜+1.0%/月 のレンジ下方寄りで、年 ¥100k 目標の達成確度は docs の印象より大幅に低い。

**最優先で直すべき1件: F-1（サーキットブレーカー）**。理由: コード上の明確な欠陥で、戦略の良否と無関係に数ヶ月以内にほぼ確実に発動し、発動中は保有ポジションの出口管理まで止まる（実損に直結する運用上の欠陥）。修正は小さく（判定量を純損失に変更＋発動中も HOLDING 出口評価は継続＋Slack 文言修正）、F-2/F-3 の統計的再評価と独立に今すぐ実施できる。

F-2/F-3 への対応は「backtest にギャップ約定モデルとブラックアウト・T+2 を実装 → 拡張グリッドを再評価 → 運用判定基準の閾値を WF OOS ベースで再設定」の順を推奨する。パラメータ・constants は本レビューでは一切変更していない。
