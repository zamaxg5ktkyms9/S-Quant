## リスク制約

| 項目 | 内容 |
|---|---|
| 1銘柄の最大損失 | **1銘柄予算 × 2.5%** ≒ Phase 1 で約 ¥2,500／銘柄（1銘柄予算 ¥100,000 × 2.5%） |
| 同時保有上限 | Phase 1: 2銘柄、Phase 2/3: 3銘柄 |
| 最長保有期間 | 各銘柄 5営業日（タイムストップ） |
| 累積損失上限（ポートフォリオ全体） | **投資資本の 15%**（Phase 1: ¥30,000）でサーキットブレーカー発動・全停止 |
| ギャップアップ回避 | 各銘柄独立判定。始値が前日終値 +2% 超ならその銘柄のエントリーを見送る（他銘柄は継続）|

### サーキットブレーカーの定義（2026-07-03 明確化）

従来「年間損失上限」と表記していたが、実装は暦年ではなく累積判定のため、以下の通り定義する:

- **判定対象**: **Phase 開始来の累積実現損失**（含み損は対象外。個別銘柄ではなくポートフォリオ合計）
- **発動時**: 全取引を停止し Slack に通知。再開は**手動リセットのみ**とし、リセット前に Walk-Forward 再検証（現行レジームでの robust 確認）を必須とする
- **リセット時期**: Phase 移行時に累積カウンタをリセットし、新 Phase の投資資本で閾値を再計算する（Phase 1: ¥30,000 / Phase 2: ¥45,000 / Phase 3: ¥150,000）

### 受容するテールリスク

単元株 + 逆指値で **ザラ場暴落は自動損切り** されるため、S株時の最大の構造リスクは解消。残るテールリスクは以下のみ:

1. **寄りギャップダウン**: 翌朝の始値が想定エントリー価格より大幅安の場合、エントリー価格自体が悪化し、その時点で-2.5%を超えていれば即座にストップ発動して大きく損失確定する可能性。
   - **緩和策**: 始値確認後に「想定ストップ価格を始値時点で割り込んでいたらエントリー自体を見送る」運用ルールを追加。
2. **ストップ価格を大きく飛び越えるザラ場暴落**: 逆指値は逆指値到達後「成行」になるため、流動性が薄いと滑る。
   - **緩和策**: 5日平均売買代金 ¥1億以上の流動性フィルタ。

## 運用上の制約

- **データ**: J-Quants Lightプラン（60 req/min）を使用。レートリミット（429）に対してバックオフと再試行を実装。
- **決算回避**: 決算発表の前後3営業日は対象銘柄から除外（ギャップリスク回避）。
- **半自動**: 発注・OCOセット・トレーリング逆指値更新は手動。システムはシグナルと推奨株数・推奨ストップ価格を Slack 通知する。
- **SBI証券の注文機能**:
  - 単元株（100株単位）取引では指値・成行・**逆指値・OCO・IFD・IFDO** が利用可能。
  - 国内株式現物手数料は「ゼロ革命」適用で **0円**（条件: 各種報告書の電子交付設定）。

## 運用判定基準（移行・撤退・保留）— 2026-07-03 追加

Phase 移行判断を「上方基準のみ」から**3値判定**に改める。月 3〜6 取引 × 2〜3ヶ月（10〜18 取引）では 1 取引あたりの分散（±2% 程度）に対して判定閾値がノイズに埋もれるため、**最低取引数を判定の前提条件**とする。

| 判定 | 条件 | アクション |
|---|---|---|
| **移行**（Phase N → N+1） | 累計 **30 取引以上** かつ 月平均リターン > +0.4%（C-WF OOS 平均 +0.28% を上回る） | Phase 移行チェックリスト（付録）を実施 |
| **撤退（停止・再検証）** | 次のいずれか: ① サーキットブレーカー発動 ② **3ヶ月連続で月次マイナス** ③ 累計 30 取引以上で実測月平均が C-WF OOS 最悪窓（W1: -0.54%）を下回る | 新規エントリー停止（保有分は出口ルールで手仕舞い）→ 現行レジームで WF 再検証 → 戦略改修 or 廃止を判断 |
| **保留（延長）** | 上記いずれにも該当しない（取引数不足を含む） | 現 Phase を継続し翌月再判定。取引数がまったく積み上がらない場合はユニバース健全性（下記）を確認 |

## 運用継続性（可用性）— 2026-07-03 追加

| 事象 | 対応 |
|---|---|
| J-Quants 障害・データ未確定 | 当日のシグナル生成を**スキップ**（シグナルなし扱い）し、Slack に skip 理由を通知。yfinance フォールバックは接続確認用であり、シグナル判定には使わない（データソース混在によるバックテスト整合性の崩壊を防ぐ） |
| GitHub Actions 実行失敗 | Slack 通知で検知。翌営業日の実行で自然回復（当日分のシグナル機会は逸失として許容） |
| オペレーター不在（発注不能） | 新規エントリーは見送り（機会逸失として許容）。**保有分は OCO が自動執行するため損失は制御済み**。トレーリングストップ未更新は「ストップ幅が広いまま」という許容劣化。タイムストップ売却ができない場合は**翌営業日に成行で実施**（1日超過は許容） |
| earnings_calendar.csv の鮮度 | **四半期ごと**（ユニバース再スクリーニングと同時）に更新。加えて決算シーズン（2・5・8・11月）の前月末に鮮度確認。カレンダーが古いと決算ブラックアウトが機能しないため、更新漏れはリスク制約違反として扱う |

## ユニバース健全性の監視 — 2026-07-03 追加

**背景（2026-06-30〜07 診断）**: 実運用で連日シグナルなしが継続。真因はバグではなく、**価格上限 ¥1,000（= ¥200,000 ÷ 2銘柄 ÷ 100株 の予算制約）**。2024〜2026 の市場上昇でファンダ全通過の優良 31 銘柄中 30 銘柄が ¥1,000 超に到達し、スクリーニング通過が backtest 期の 6〜8 銘柄/日 → 本番 1 銘柄/日 に痩せ細った。

**監視要件**:

- 日次のスクリーニング通過数（eligible universe）を記録する（Slack / Sheets）
- **通過数の 20 営業日平均が 3 銘柄未満**になったら構造レビューをトリガーし、以下の選択肢からユーザーが判断する:
  1. **予算増額**: ¥200k → ¥400k で価格上限 ¥2,000（2026-06 時点データで候補 ≈ 11 銘柄に回復）
  2. **単元未満株（S株）の再導入**: 100株単位制約を外す（発注フロー・出口執行の構造変更を伴う）
  3. **低頻度を許容**: 現行のまま運用（機会損失を受容）
  4. **スクリーニング緩和 + WF 再検証**: 流動性・PBR 閾値の緩和はシグナル品質の前提を崩すため、`walk_forward.py` での再検証を必須とする

> **注意**: 診断によれば backtest でも候補 6〜8 銘柄/日の時期ですら限界的（2025Q4: PF 0.97）。ユニバース回復は「取引機会の回復」であって「収益性の回復」を保証しない。

**Phase 1 を ¥200,000 にした根拠**: ¥100,000 で 2銘柄分散すると 1銘柄予算 ¥50,000 → 株価上限 ¥500 となり、ユニバースが半減しシグナル機会が大きく不足することが B-WF / C スモークで判明。¥200,000 にすれば 1銘柄 ¥100,000 → 株価上限 ¥1,000 でユニバース全体（282銘柄）が使え、A1/B/C 戦略を同じ価格帯で公正比較できる。

**Phase 1 で 2銘柄に絞る根拠**: ¥200,000 ÷ 3銘柄 ÷ 100株 = ¥666/株が理論上限となるが、3銘柄目に至るまでに動的予算が小さくなり実発注しにくいケースが想定されるため、Phase 1 は安全側で 2銘柄分散とする。Phase 2 (¥300k) 以降で 3銘柄へ拡大。
